# Algebraic differential equations (#29)

## Design

Keep CVODE for ODE models and use SUNDIALS IDA for models with algebraic rules.
Append the unknowns of algebraic equations to the differential state vector. Match
rules to eligible nonconstant entities deterministically with maximum bipartite
matching, respecting the variables already determined by rules and reactions.
Prefer variables without explicit initial values or event assignments when the
model allows several matches.

The existing compiled RHS and Jacobian exports evaluate the differential rates
followed by algebraic residuals, and their derivatives with respect to all states.
An optional `n_algebraic` description field identifies the algebraic suffix. ODE
descriptions retain their existing serialization and exports. IDA constructs the
residual `[f - y', g]` and the Jacobian `d(f,g)/dy - cj diag(1,...,1,0,...,0)`.

Compute consistent algebraic values before initial output and event evaluation,
and after changes and event assignments. Reuse the existing output, event,
prepared-request and steady-state behavior. Support pure algebraic models and
the dense and KLU linear solvers with analytic or difference Jacobians.

## Implementation ownership and sequence

1. Compiler: ABI metadata, variable matching, IR lowering, differentiation,
   optimization, discontinuity detection, and focused compiler tests.
2. Solver: vendored IDA build and FFI, resource-owning backend, consistent
   initialization and reconciliation, integration lifecycle, and solver tests.
3. Integration: host initial selections, native/WASM/prepared regressions,
   documentation, suite baseline generated by the runner, and final review.

The compiler and solver implementations proceed in parallel against the shared
partition and export contract. Integration and review follow their first working
end-to-end result.

## Acceptance

- Exercise all 123 cases refused for algebraic rules by the baseline. Three also
  use the separately unsupported MathML `delay` csymbol. The expected improvement
  is 120 newly passing cases, with the delay diagnostic for those three.
- Run the complete prepared SBML Test Suite with optimization on and off and with
  the difference Jacobian, including repeatability checks.
- Verify native, WASM and JavaScript execution, prepared requests, initial
  selections, changes, initial events, cascades and pure algebraic systems.
- Run formatting, clippy, relevant Rust tests, WASM builds, and JavaScript tests.
- Preserve warmed ODE performance. Compare the final release builds in paired
  baseline/feature blocks in both orders, with matching result bits and all 13
  counters. Cover dense and KLU, analytic and difference Jacobians, Adams,
  ordinary and prepared requests, and zero-duration output. Report engine size
  and uncached startup separately.
- Cover initialization dependencies and concentration conversion involving an
  algebraic compartment, which the prepared algebraic suite does not cover.

## Validation results

The full SBML Test Suite passes 1,701 of 1,789 cases in optimized, unoptimized and
difference-Jacobian modes, with no unexpected failures or repeatability failures.
All 120 supported algebraic-rule cases now pass. The remaining three algebraic
models also use the separately unsupported MathML `delay` csymbol.

Optimizer parity passes 3,402 comparisons across both Jacobian modes. Node matches
Wasmtime for all 1,701 exported models, including prepared requests and 351
steady-state runs. The 12 host DAE regressions cover analytic trajectories, KLU's
missing differential diagonal, initial values, coupled initialization, concentration
pre-initialization, events and cached expressions, discontinuities, and steady-state
rejection for a changing algebraic value.

Rust unit, integration and documentation tests, the 57 Python tests, all 62
JavaScript checks, workspace Clippy, native/WASI solver Clippy, formatting, the
compiler WASM build, and the host/CLI build without default features pass.
