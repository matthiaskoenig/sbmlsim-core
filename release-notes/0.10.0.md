# Release notes for sbmlsim-core 0.10.0

The engine simulates models with algebraic rules. They were refused until now, the one class of SBML the compiler turned away that a simulator is expected to handle, and with them the semantic suite goes from 1,581 to 1,701 of its 1,789 cases.

## New

- **Algebraic rules, with SUNDIALS IDA** ([#32](https://github.com/matthiaskoenig/sbmlsim-core/pull/32), closes [#29](https://github.com/matthiaskoenig/sbmlsim-core/issues/29)). A model with algebraic rules compiles into residual equations and integrates with IDA. The compiler matches each equation to an eligible non-constant variable and appends these unknowns to the state vector; a variable determined by an assignment rule, a rate rule or a reaction keeps the role it has, and an overdetermined system is a compilation error. IDA integrates regular index-1 systems, whose algebraic equations have a non-singular Jacobian with respect to the matched unknowns along the solution.

    An algebraic variable is determined by its constraints, so the initial value the SBML gives it is a guess for the consistency solve and a change or a pre-initialization targets the independent variables. The constraints are solved before the initial output and the event triggers, and again after a change and after the assignments of an event, so initial assignments and the conversion of a species concentration use the consistent values. Pure algebraic models work as well. Both the analytic and the difference Jacobian and both the dense and the KLU linear solver are available, and IDA uses BDF whatever the `stiff` of the request says. `model.json` carries `n_algebraic`, the length of the algebraic suffix of the state vector, which an ODE model does not have.

    **What it covers**, from the semantic cases of the SBML Test Suite: 1,701 of 1,789 pass where 1,581 did, in the optimized, the unoptimized and the difference-Jacobian modes alike, and all 120 supported algebraic-rule cases pass. The three algebraic cases which still fail need the `delay` csymbol, which the engine does not implement for any model. The baseline, the coverage grid and the documentation are updated with them.

    **What it costs an ODE model**, measured rather than assumed: an ODE model keeps a separately specialized CVODE path and no solver callback dispatches on whether the model is a DAE. A frozen confirmation experiment over 24 ODE scenarios, with 24 baseline and feature processes and eight identical-engine controls, resolved no slowdown, but 14 of those scenarios stayed unresolved, the largest simultaneous upper bound allows 6.1 %, one identical-engine control flagged measurement variation, and a separate native comparison measured 9.3 % higher median CPU time over its 24 scenarios. These numbers do not establish that the feature is free; the cost is accepted for DAE support and written down in [`bench/ODE_PERFORMANCE.md`](https://github.com/matthiaskoenig/sbmlsim-core/blob/develop/bench/ODE_PERFORMANCE.md) with the raw measurements.

## Documentation

- **A live simulation in the documentation** ([#30](https://github.com/matthiaskoenig/sbmlsim-core/pull/30)). The JavaScript page runs the repressilator on a slider: the Hill coefficient `n` moves and the model is compiled and integrated in the reader's own browser by the same engine the command line and the wheel run, with the result drawn as inline SVG and its numbers in a table below it.

- **The badges on the overview and a diagram on four pages** ([#34](https://github.com/matthiaskoenig/sbmlsim-core/pull/34), [#28](https://github.com/matthiaskoenig/sbmlsim-core/pull/28)). The badges of the README open the overview, with the license badge pointing at the Licenses page of the site rather than at a file the site cannot follow. The diagram style lives in the stylesheet the site already loads, so the overview, the compiler page, the simulation page and the JavaScript page each draw one from the tokens of the theme: the program and its two contracts, what the compiler takes and writes and what it refuses, the stages of one request with the segments of the integrator below them, and the worker pool with its runtime per worker. The navigation has sections, the test suite has a grid of its coverage and there is a page for the Rust API.

- **The benchmark figure and tables are ordered by host** ([#27](https://github.com/matthiaskoenig/sbmlsim-core/pull/27)), mark which host is the wheel and show the spread of every measurement.
