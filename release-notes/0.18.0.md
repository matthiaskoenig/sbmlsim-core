# sbmlsim-core 0.18.0

Two fields of `simulation/1` which close the last three gaps of [sbmlsim](https://github.com/matthiaskoenig/sbmlsim) on the PEtab v2 test suite: of its 31 cases 30 are now a fit of the engine, where 23 were at 0.17.0, and the one which is not has parameters with a prior and no bounds, which is no gap of the engine.

## The state before the events of a time, `before_events` (#19)

A request answers the end of its interval with the state **after** the events of that time, which is what a timecourse reads. A caller which folds the value of a change into a number needs the other one: libroadrunner evaluates the triggers and applies a change *before* it executes the events of that time, so the formula of the change reads the state before them.

`"before_events": true` is that request:

```json
{ "contract": "simulation/1", "start": 0.0, "end": 5.0, "output": { "times": [0.0, 5.0] }, "before_events": true, "selections": ["time", "x"] }
```

The events of the end are not executed at all, the simulation ending there, and the last row is the state the end was integrated to with the changes and the events before it applied. Only the end is affected: an output time inside the interval sees the state after the events of its time, as it does without the flag. The flag holds for every kind of output, the steps of the integrator included, where the two rows of an event at the end become the one row before it.

Measured on the probe of the issue, the event `x >= 5: p = p + 10` at the time 5: a request which ends at 5 answers `p` 10, a request with the flag answers 0, which is what roadrunner folds. The field is `false` by default, which is the request every release before this one reads.

Before it, sbmlsim probed one unit in the last place before the time of the change and refused a formula which reads a target an event of the model moves, since the engine executes an event of a time for an end within about 1e-9 of it, far wider than the unit in the last place CVODE resolves, so no probe could tell the two states apart. That refusal is gone; cases 0016 and 0030 of the PEtab test suite are fits of the engine now.

## A steady state after the end, `steady_state_after` (#60)

`steady_state` is the pre-equilibration before the start. `steady_state_after` is the same criterion applied **after** the timecourse, which is a measurement at steady state, PEtab v2's time `inf`:

```json
{ "steady_state_after": { "from": 0.0, "absolute_tolerance": 1e-8, "relative_tolerance": 1e-6, "max_time": 1e8 } }
```

The model continues from the state the timecourse of the same request ended in, with the triggers of its events as it left them and every pending execution moved from the end to `from`, and is integrated from `from` over horizons which grow by a factor of ten, as the pre-equilibration is. Its row is the last of the output, at the time `inf`; the rows of the timecourse are the ones of a request without it, bitwise. A steady state which is not reached is an error of the integration, with the flag of the pre-equilibration.

Carrying the triggers is what the field is for. A caller which runs the steady state as a second request has to carry the state the timecourse ended in through a pre-initialization, which initializes the model: an event whose trigger that state makes true executes again, where libroadrunner, continuing its own model, does not. On case 0023 of the PEtab test suite, whose event adds 1000 to its state at a threshold its steady state is past, the second request answered 2500 against roadrunner's 1500; the field answers 1500.

`from` is the time the integration to the steady state starts at, 0 by default, which is where libroadrunner integrates the steady state of a model whose math does not read the time; a caller which continues a model which reads the time passes the end of its timecourse, as roadrunner does, so the two agree whatever the model. The field is absent by default, which is the request every release before this one reads.

## Tests

`crates/engine/tests/events.rs` grows seven tests. `before_events` has the state before the event of the end against the state after it on the same request, the events inside the interval untouched (every row of such a run is the row of a request without the flag) and the steps of the integrator, where no row of the run carries the execution. `steady_state_after` has the row at the time `inf` as the last of the output, the event of the timecourse not executed again (checked from a timecourse which ends before the event and from one which ends after it, both of which reach the same steady state), a model without events, and a model which never reaches one as the error of the integration.

`cargo test --workspace` is green (74 suites), `cargo clippy --workspace --all-targets` and `cargo fmt --check` are clean.
