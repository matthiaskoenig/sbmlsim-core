# Release notes for sbmlsim-core 0.5.0

Repeated simulations reuse model metadata, solver storage and worker instances.
Prepared requests support parameter scans with numeric inputs across Rust, Python
and JavaScript. The hosts apply bounded execution and resource policies, and the
default Rust host has fewer dependencies and capabilities.

## New

- **Prepared simulations.** Rust `Engine::prepare` / `simulate_prepared` and host
  plans resolve a fixed request once. Python exposes `model.prepare`,
  `instance.simulate_prepared` and `executor.simulate_prepared`; JavaScript exposes
  `instance.prepare` / `simulatePrepared` and asynchronous pool equivalents.
  Varying targets retain pre-initialization order and quantity. Plans are bound to
  their model, with at most 32 live guest plans per instance.
- **Persistent Python batches.** `model.batch_executor()` retains workers and
  instances across submissions, closes through a context manager, and supports
  ordered, bounded streaming with `simulate_stream`.
- **Reusable simulation storage.** Entity and selection lookups, finite-difference
  workspace, initialization, event and segment buffers, and aligned host input
  buffers survive successive runs. Output arrays retain independent ownership.

## Fixes and hardening

- Bound function expansion, analytic derivative construction and XOR root
  generation. Explicit difference quotients skip analytic derivative construction.
- Contain native callback panics and model traps; failed instances refuse reuse.
- Apply a 30-second execution deadline by default. Configure it with CLI
  `--timeout-ms`, Python `Runtime(timeout_ms=...)`, Rust runtime settings, or
  JavaScript pool `deadlineMs`. Zero disables the deadline in the CLI, Python and
  JavaScript settings; Rust uses `None`.
- Bound pending events, retained event assignment values, worker models, queues,
  input bytes and aggregate pool memory. Exceeding the event storage policy returns
  integration flag `-1005`.
- Validate JavaScript model bytes before instantiation and recover pool slots
  after dispatch failures, worker exits, cancellation and timeouts. Bound panel
  caches and runs in flight, with failed runs removed from the cache.
- Replace the full Rust WASI implementation with a minimal adapter: bounded local
  diagnostic capture, an empty environment, and trapping unsupported capabilities.
  Retain readable trap backtraces.

## Compatibility

- The contracts remain `model/2` and `simulation/1`. Ordinary simulations work with
  older runtimes; prepared execution requires the new optional engine exports.
- The native host adapter is opt-in. Build with `--features native` to use
  `bench --host native` or `Runtime::instantiate_native`.
- `EngineError` is defined in `sbmlsim-abi` and reexported by the engine and host.
- Execution and resource limits can reject workloads that previously ran without
  bounds. Configure host limits for trusted larger or longer simulations.
- The 0.4.0 inline browser build and embedded Python runtime remain supported.
