# sbmlsim-core 0.36.0

SBML equation analysis and source generation now belong to the shared Rust core.
Python, Diffrax/JAX, Julia, R, Markdown, LaTeX and Typst use one resolved equation
plan, expression writers and embedded templates. Native Python, the CLI and
import-free browser WASM expose the same generator.

- `sbmlsim_core.OdeSystem`, `ODE_FORMATS`, `OdeFormat` and `render_ode` provide
  standalone source exports and linked equation data. Read original SBML text,
  bytes or trusted paths; original bytes preserve double precision.
- The CLI adds `export`, with file or stdout output, simulator/fragment options
  and identifier/name symbols. The JavaScript compiler adds `exportOde`.
- Portable `sbmlsim-document`, `sbmlsim-reader` and `sbmlsim-ode` crates share the
  lossless SBML model, pure Rust reader, confined comp resolution and equation
  analysis with sbml4humans-core. Native filesystem discovery is an optional
  adapter; browser and untrusted sources resolve explicit companions only.
- Python wheels support 3.12 through 3.15 with one `cp312-abi3` build per platform.
  Generation needs no libSBML, Jinja2, SciPy or JAX; those numerical libraries are
  required only to execute their generated targets.
- Complete native/WASM fixtures preserve the former sbmlode outputs, apart from
  generator headers. Executed NumPy event/dilution models and Diffrax models and
  gradients preserve numerical results. All 1,789 simulation suite cases retain
  the existing baseline, including 1,754 passing cases.


See [ODE source exports](https://matthiaskoenig.github.io/sbmlsim-core/odes/) for formats, options, companion sources, templates and migration from sbmlode.
