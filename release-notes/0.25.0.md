# sbmlsim-core 0.25.0

The engine took six settings of the integrator and ignored the rest. What was missing is what a verification of the numerical error needs and what anybody debugging a stiff model asks for first: the order of the method, the smallest step, the bounds of the error test and of the nonlinear solver, the detection of the stability limit, and the state the solver ended in.

## Features

- **The order of the method.** `maximum_bdf_order` (1 to 5) bounds the BDF of CVODE and of IDA, `maximum_adams_order` (1 to 12) the Adams method of `"stiff": false`; `0` is not set, as before. An order above the method is refused by name. A second integration of the same request at a lower order is how a caller bounds the error of the solver itself, which is what sbmlsim's credibility verification does with its factor `integrator`: until now the engine answered that second run with the numbers of the first.

- **The steps, the error test and the nonlinear solver.** `minimum_time_step` (`CVodeSetMinStep`, `IDASetMinStep`), `maximum_error_test_failures`, `maximum_nonlinear_iterations`, `maximum_convergence_failures` and `nonlinear_convergence_coefficient` reach CVODE and IDA both. `0` and `0.0` keep the default of the solver, so a request which does not name them integrates exactly as it did; a `minimum_time_step` above `maximum_time_step` is refused. The 30 error test failures the engine allows a model of algebraic rules, for the rate the consistent initial values have to find, are its default and not a cap: a request which names `maximum_error_test_failures` gets what it named.

- **The stability limit and the algebraic states.** `stability_limit_detection` turns on `CVodeSetStabLimDet`, for a model whose dominant eigenvalues lie near the imaginary axis, and the statistics count the reductions of the order it made. `suppress_algebraic` leaves the algebraic states of a model out of the error test of IDA. Each is refused where the method has no such setting: the detection with `"stiff": false` and for a model of algebraic rules, the suppression for a model without them. The engine still turns the suppression on of its own where it interpolates over an algebraic jump.

- **The state of the solver in the statistics.** The statistics carry seven values after their counts: `stability_order_reductions`, `last_order` and `current_order`, `actual_initial_time_step`, `last_time_step`, `current_time_step` and `current_time`. A run which seems to hang is read from them - how far the integrator got, how small its steps became, and which of the two tests drove them down - without swapping in another solver. They are of the integration which stepped last, never of the projection of the consistent initial values which follows it for a model of algebraic rules.

  The block of `engine_stats_ptr` grows from 21 words to 28. The first `SimulationStats::COUNTS` (24) of them are counts; the four after them are the bits of their `f64`. `Instance::stats` in rust, `instance.stats()` in python (ints and floats now) and `instance.stats()` in JavaScript (`STATS_NAMES`, `STATS_COUNTS`) read them.

Found while reassessing the HCTZ model of pkdb_models on sbmlsim 0.38.0 (matthiaskoenig/pkdb_models#546); the settings close matthiaskoenig/sbmlsim-core#85 and unblock matthiaskoenig/sbmlsim#635.
