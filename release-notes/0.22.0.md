# sbmlsim-core 0.22.0

A fit can read more than one model: every condition of a request of `fit/1` names the model it simulates, and the pool of the fit holds an instance of every model its points met.

## A fit of several models (#72)

A fit of one model could not be given data which belongs to two models, e.g. the two builds of a model of a drug, one per sex, or the model of a study which measures two species. The conditions of a request of `fit/1` all simulated the one model the fit was created with, so a caller had to fit the two halves of such a problem separately, which estimates the parameters they share twice and against half the data each.

A condition now names its model:

- `ConditionRequest.model` is the id of the model the condition simulates, one of the models of the fit. It is absent for a fit of one model, which every condition simulates, so every request of a release before this one is read as it was.
- `sbmlsim_core.fit_models(models, request, threads=..., on_run=...)` is the fit of several models, with the loaded models by the id their conditions name them by, and `sbmlsim_core.fit_problem_of_models(models, request, threads=...)` their problem for an optimizer which stays in python. `LoadedModel.fit` and `LoadedModel.fit_problem` are the fit of one model as before.
- A condition which names a model the fit has not, or which names none although the fit has several, is refused before anything is simulated, and so is a mapping of no model or one which holds something that is no loaded model.
- The parameters of the fit are the same in every model it reads: a parameter is one value of the search, applied to its target in the model of every condition it reaches.

In Rust, `Problem::of_models(definition, models, threads)` takes the models by their id and `Condition.model` is the id a condition names, while `Problem::new` is the fit of one model as before. `Workers::of_models` is a pool of several models, whose thread holds an instance of every model its points met, and `Workers::map_at` routes a point to its model: the start simulation, the residuals, the jacobian of the sensitivities and the profiles all run a condition on the model it names. A pool of two models is twice the memory of a pool of one, the instances being made at the first point of their model, so a fit of two models of 700 kB of description costs one more instantiation per thread.

For [sbmlsim](https://github.com/matthiaskoenig/sbmlsim) this is the last feature the fit problems of the dependent model corpus need: the nine problems which are still fitted in python are the ones whose fit mappings read two models.
