# sbmlsim-core 0.39.0

PEtab v2 runs in JavaScript: a page reads, simulates and evaluates a problem with the bits of the command line, on the `compiler.wasm` of every build, which now carries PEtab (#149, fixes #143).

## PEtab v2 in JavaScript (#149)

- **Module.** `js/petab.mjs` (`sbmlsim-core/petab`) drives the PEtab interface of
  `compiler.wasm`: `openPetab({ compiler, runtime, files })` reads, plans and compiles a
  problem from the contents of its files (text or bytes by name), `evaluate` simulates the
  requests of the plan on the loader or on the workers of a pool and gives the log-likelihood,
  `chi2`, the log prior, the log posterior and the simulation table, `simulations` gives the
  time courses and `close` drops the problem.
- **The same bits everywhere.** The fit of the pharmacokinetics of hydrochlorothiazide of
  pkdb_models evaluates to the identical log-likelihood (`1620.2615718892766`) in Node, in
  Chrome and in Rust (`sbmlsim-core petab`).
- **`compiler.wasm` carries PEtab.** The feature `petab` of `sbmlsim-wasm` is on by default, so
  the compiler of the npm package, of the python wheels and of the command line evaluates a
  problem: 3.07 MB to 3.41 MB raw, +112 kB gzipped. A module of its own would have held the
  whole compiler again; `cargo build -p sbmlsim-wasm --no-default-features` builds the compiler
  alone.
- **Exact values.** `petab_evaluate` takes the simulated values as the raw bytes of their
  `f64`s, so they cross exactly, `NaN` included. Numbers which are not finite are the strings
  `"NaN"`, `"Infinity"` and `"-Infinity"` in the answers, which `Number` of JavaScript reads
  back, instead of `null`.
- **Inline build.** The inline build of the python package (`sbmlsim_core.web.script()`)
  exports `openPetab`, `createCompiler` and `createRuntime`, for a page of one file which
  evaluates a problem with the bytes of `sbmlsim_core.runtime_wasm()`.
- **Command line.** `sbmlsim-core petab` prints its log-likelihood, `chi2` and log prior at
  full precision.
- **Tests.** `js/test/petab.test.mjs` checks the analytic solution, the pool against the loader,
  the inline build, the command line bit for bit and the cases of the PEtab test suite (51
  pass) in Node; CI builds the command line of the loader tests with the feature `native` and
  downloads the cases.

A fit of a problem in a page is not supported yet: the optimizers are `sbmlsim-fit`, which runs
on the native host.

See [JavaScript](https://matthiaskoenig.github.io/sbmlsim-core/javascript/#petab-problems) and
[PEtab](https://matthiaskoenig.github.io/sbmlsim-core/petab/#in-a-browser).

## Behaviour changes

- `compiler.wasm` is built with the feature `petab` by default and grows from 3.07 MB to
  3.41 MB (+112 kB gzipped) (#149).
- `petab_evaluate` of `compiler.wasm` takes the values of the results as the bytes of their
  `f64`s instead of JSON numbers, and the answers of the PEtab calls write numbers which are
  not finite as the strings `"NaN"`, `"Infinity"` and `"-Infinity"` instead of `null` (#149).
- `sbmlsim-core petab` prints its numbers at full precision instead of ten digits (#149).
