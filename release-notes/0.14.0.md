# Release notes for sbmlsim-core 0.14.0

The forward sensitivities of a run reach python: a simulation which asks for them answers with the derivative of every column of every row in every parameter, which a local sensitivity analysis reads instead of taking differences of whole simulations.

## New

- **The forward sensitivities of a simulation on its output** ([#55](https://github.com/matthiaskoenig/sbmlsim-core/pull/55), for [sbmlsim#555](https://github.com/matthiaskoenig/sbmlsim/issues/555)). A request which carries `sensitivities` answers with them on the output of `simulate` and of `simulate_many`, `None` for a request which asks for none:

    ```python
    request["sensitivities"] = ["k"]
    out = model.instance().simulate(request)
    out.sensitivities.parameters  # ["k"]
    out.sensitivities.values.shape  # (rows, columns, parameters)
    ```

    `values` is a float64 array in C order, the derivative of the column `c` of the row `r` in the parameter `j` at `[r, c, j]`, the layout of `Sensitivities` of the ABI as an array rather than as a flat list. The column of the time is no function of a parameter, so its derivatives are 0.

    They are what the engine integrated next to the states (CVODES, `CV_STAGGERED`, see [Forward sensitivities](https://matthiaskoenig.github.io/sbmlsim-core/simulating/#forward-sensitivities)), so one run of `k` parameters answers what `k + 1` runs of a finite difference answer and to the tolerance of the integration instead of the step of a difference: on the decay model `dy/dk` is `-t exp(-k t)` to 3e-5 of itself at a relative tolerance of 1e-6. The crate carried them since 0.12.0 for the Jacobian of a fit, where they never left Rust; this is the same table for a caller of a simulation.

    The native engine computes them, as it did before, and a request which asks for them through `engine.wasm` is refused, whose output format has no room for a second table.
