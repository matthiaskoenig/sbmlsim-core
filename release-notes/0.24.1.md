# sbmlsim-core 0.24.1

A profile which walks into a bound of its parameter holds it at that bound. The walk steps in the space the parameter is searched, and the way back from that space is not always the number the bound went in as, so a profile which reached the bound of a parameter searched on `log10` failed instead of ending there.

## Fixes

- **A step onto a bound is the bound.** The walk of a profile clamps its step to the bound of the parameter in the search space and converts that value back for the point it holds: `10^log10(0.0024)` is `0.0023999999999999994`, one ulp below the bound, which `Problem::fixing` refuses as a value outside the bounds of its parameter. The whole analysis then failed with `the parameter '<id>' is held at <value>, outside its bounds [<lower>, <upper>]`, although the walk had asked for the bound itself. The value a point holds is clamped to the bounds of its parameter now, and the value it reports is the one it held. A parameter whose profile does not reach a bound is unaffected, bitwise; a profile which reaches one ends there, with the point at the bound, as it was meant to.

  A parameter the data does not determine on one side is what walks into its bound, so the defect met exactly the profiles which say that the data do not determine a parameter. Whether it was reached depended on the bound alone: `0.01` and `10` round trip through `log10` exactly and the walks of the tests ended at them, `0.0024` does not.
