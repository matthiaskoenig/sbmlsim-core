# Release notes for sbmlsim-core 0.4.0

A panel app is one HTML file: the python package carries the runtime and an inline build of the JavaScript host, with which a page embeds a bundle and its models compiled in python and simulates them in the browser without a server, also opened from `file://`. sbmlsim writes the app of a model so. The results of a simulation are the ones of 0.3.0.

## New

- **The inline build of the JavaScript host** (`js/inline.mjs`, `node js/build.mjs`): one classic script with the global `sbmlsimCore`. `createInlineEndpoint({ bundle, files, engine, mathlib })` is the panel endpoint of a bundle held in memory, whose pool starts its workers as classic workers from a `blob:` URL of the embedded worker (`WORKER_SOURCE`), so a page of one file needs no server and no network. The build is committed into the python package and checked against the sources by the tests (esbuild is a development dependency of `js/`, locked).
- **The runtime and the inline build in the python package.** `sbmlsim_core.runtime_wasm()` gives the bytes of `engine.wasm` and `mathlib.wasm` the extension embeds, `sbmlsim_core.web.script()` the inline build and `sbmlsim_core.THIRD_PARTY` the notices of the libraries of the engine, which a page that distributes it carries.

## Fixes

- **The worker runs as a classic script**: `worker.mjs` has no top-level await, its thread of Node takes the port from a promise.
- **The golden files of the contracts are tested in Node** (`js/test/golden.test.mjs` was not imported by the index of the tests, so `node --test js/test` skipped it).
- **The temporary directories of the tests of the JavaScript host are removed** when their process exits; every run left the compiled bundles and runtimes in the temporary directory.
