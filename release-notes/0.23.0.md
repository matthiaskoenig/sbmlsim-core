# sbmlsim-core 0.23.0

A page compiles its own models: `compiler.wasm` is the compiler of this package for the browser, and `sbmlsim-core/compile` is its JavaScript host.

## The compiler in the browser (#79)

A model had to be compiled ahead of time. The command line or the python binding wrote `model.wasm` and its description, and a page could only run what it was given, so a page which lets a visitor drop a model in had to send the document to a server to get a module back - the one thing this project does not need a server for.

```js
import { createCompiler } from "sbmlsim-core/compile";
import { createRuntime } from "sbmlsim-core/loader";

const compiler = await createCompiler({ compiler: compilerWasm });
const runtime = await createRuntime({ engine, mathlib });
const { wasm, description } = compiler.compile(sbmlText);
const instance = await runtime.instantiate(wasm, description);
```

- `compiler.wasm` (640 KiB) is the compiler of the command line built for `wasm32-unknown-unknown`, behind the C ABI of `allocate`, `compile` and `deallocate`: the document goes into the memory of the module as the bytes of its UTF-8, the result comes back as the description and the bytes of `model.wasm`, and a document the compiler refuses gives its message instead. It reads no file and imports nothing of a host.
- `createCompiler({ compiler })` takes the module or its bytes and checks its exports. `compile(sbml, { optimize = true, jacobian = "auto" })` is synchronous and gives `{ wasm, description }`, which `runtime.instantiate` takes as they are, and raises a `CompileError` with the message of the compiler for a model it refuses. One compiler compiles any number of models.
- The module is part of the package in three places: `sbmlsim-core runtime -o DIR` writes it next to `engine.wasm` and `mathlib.wasm`, the npm package ships it as `sbmlsim-core/runtime/compiler.wasm`, and `sbmlsim_core.runtime_wasm()` of the python package gives its bytes under the key `compiler`, so a page gets the compiler of the version it simulates with without a CDN.

What a compilation in the browser gives is what the command line gives: the tests of the package compare the module and the description of a compilation in Node with the ones of `sbmlsim-core compile` byte for byte, and a simulation of both gives the same bits.

[sbml2cellml](https://github.com/matthiaskoenig/sbml2cellml) converts SBML to CellML and back in a browser and simulates the CellML side there with libopencor. With this release its online converter compiles the SBML side as well, so one model runs in both simulators on the same page.
