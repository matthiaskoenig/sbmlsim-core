# sbmlsim-core 0.17.0

## A condition of a fit carries values which follow its parameters

A value of a request of `simulation/1` is a number, so a condition whose value is a parameter the fit estimates could not be a condition of a fit: the number folded when the request was built holds that value where the fit started, while the optimizer moves the parameter. That is the shape of a PEtab condition which assigns a species an estimated parameter, e.g. `[B] = initial_B` or `[A] = initial_A1 + initial_A2`, which is why [sbmlsim](https://github.com/matthiaskoenig/sbmlsim) fitted such a problem in python rather than in the engine.

A condition of `fit/1` now carries those values as `derived`, each a linear form over the parameters of the fit:

```json
{
  "id": "c0",
  "request": { "contract": "simulation/1", "end": 10.0, "output": { "uniform": { "steps": 10 } }, "selections": ["time", "y"] },
  "derived": [
    { "target": "y", "constant": 0.0, "terms": [{ "parameter": 0, "factor": 1.0 }] }
  ]
}
```

The fit evaluates `constant + Σ factor * parameter` on the linear scale of the parameters at the values the optimizer is at, and sets it on its target as a pre-initialization of the condition before every simulation, which is what a varying target of a prepared request already is (`Engine::prepare`: a varying id overrides the pre-initialization slot of its entity or appends one). The target has to be a settable entity which is no parameter of the fit and no other derived value of the same condition, and a term reads a parameter of the fit by its position.

`derived` is absent by default, which is the request every release before this one reads, so nothing changes for a caller which does not set it, and a condition without derived values hands the values of the parameters through without allocating.

A fit whose conditions carry derived values takes the difference quotients of its optimizer for its jacobian, whatever `jacobian` asks for: a derived value follows more than one parameter in general, which the one parameter per varying target of a block of the forward sensitivities cannot carry.

## Tests

`crates/fit/tests/derived.rs` is ten tests on the decay model, whose initial value of `y` follows `k`. What they hold the fit to is that the value is **not frozen**: the residuals at a point of the search space are the ones of the model simulated with the value that point gives, compared with a direct simulation at that point, and they differ from the ones of a value held where the fit started. A fit from another start finds the parameter again, a value of a constant alone is set on its target, and a target which is a parameter, a target named twice, a term which reads a parameter the fit has not, a factor which is not finite and a value without a target are each refused by name.

`cargo test --workspace` is green (74 suites), `cargo clippy --workspace --all-targets` and `cargo fmt --check` are clean.
