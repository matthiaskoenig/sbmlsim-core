# Release notes for sbmlsim-core 0.13.0

A fit of many starts reports every run as it finishes, so a caller follows a fit of minutes while it runs instead of waiting for all of it, and keeps the runs of one which was interrupted.

## New

- **A fit reports the runs which finished while it runs** ([#51](https://github.com/matthiaskoenig/sbmlsim-core/pull/51), for [sbmlsim#556](https://github.com/matthiaskoenig/sbmlsim/issues/556)). `fit_reporting` is `fit_with` with what a run of the fit is reported to, called on the thread of the pool which ran that start with the index of the start and the run of it, and `LoadedModel.fit` takes the `on_run` of python for the same thing:

    ```python
    answer = model.fit(
        request, threads=8, on_run=lambda index, run: print(index, run["cost"])
    )
    ```

    The runs are sent to the thread of the caller, which calls `on_run` with the GIL while the fit runs on, so nothing of python is touched from the pool. The runs of a fit which finished are all reported before it answers, the runs of a fit which `Ctrl-C` stopped are reported before `KeyboardInterrupt` is raised, which is what a caller keeps them by, and an error the callable raises stops the fit and reaches the caller. A run says where its jacobian came from now, as the fit of all of them does, so a run which is reported is a run of the answer and a caller needs nothing of the answer around it. `docs/fitting.md` is the page of it.

    **Not chunks of starts.** The other way to follow a long fit is to run it in chunks of a few starts, one request each, which a caller measures and keeps. It costs more than it is worth: the runs of a fit are not equally long, and a chunk ends with its longest run while the threads beside it idle, where the pool of one request work-steals across every start of it. The fits of the HCTZ example of sbmlsim (16 starts, 4 threads, the median of three runs of each, interleaved) take 1.07x (PK) and 1.34x (iv) in chunks of four starts, and more the wider the runs of a fit spread.

    What it is for is the other half of this work, [sbmlsim#569](https://github.com/matthiaskoenig/sbmlsim/pull/569): a fit of a problem of sbmlsim in the engine reports its progress, stores every run as it arrives and keeps what an interrupted fit finished.
