# sbmlsim-core 0.41.0

## Batched kernel (#151)

A model of ordinary differential equations and its integrator compile into one WebAssembly module, the batched kernel (`kernel/1`). It advances any number of instances of the model per call, for example the cells of a tissue in a page, where a call into `engine.wasm` per cell and step would cost more than the step itself.

- `sbmlsim-core compile model.xml --kernel -o DIR` writes `kernel.wasm` and `kernel.json`. The same compilation is `sbmlsim_compiler::compile_kernel` in Rust, `compile_kernel` of `compiler.wasm`, and `compiler.compileKernel(sbml)` in JavaScript, byte for byte the same.
- `sbmlsim-core/kernel` (`instantiateKernel({ wasm, mathlib, memory })`) instantiates a kernel with mathlib and the `WebAssembly.Memory` of its caller.
- The kernel exports `sbmlsim_kernel_init(n, parameters, state)`, `sbmlsim_kernel_advance(n, state, parameters, control, counts, context, scratch)` and `sbmlsim_kernel_assign(n, state, parameters, control)`, over arrays of the caller with the values of the points one point after the other. It imports only `env.memory` and functions of mathlib, and it has no data segment and no global and never grows the memory.
- `init` takes a parameter which is NaN as not given: it gets its SBML value and its initial assignment, as a parameter a simulation does not change.
- `assign` evaluates the assignment rules of every point at its time and its states and writes their targets into its parameters, as `model_assign` does in the engine, so an output which is the target of a rule of a state or of the time (the necrosis trigger of the cell model, say) has its value after an advance. `kernel.json` lists these parameters as `assigned_ids`.
- The integrator is the one of the QFunction target of the C target: RODAS4 with the same step control and fields (`t`, `h`, `done`, `failed`; the accepted and the rejected steps). On the cell model of `testdata/models` a point takes the same steps as the QFunction, its states within about `1e-14` relatively. The math functions are those of mathlib, so the results are not bitwise those of the C library. A point's steps depend on nothing but the point, so one call for all points and one call per point give the same bits.
- The kernel refuses what the QFunction refuses, naming the feature: events, delays, algebraic rules, a model without states or without an analytic Jacobian.
- The kernel advances one point after the other; SIMD is not used yet.

See [Compiling a model](https://matthiaskoenig.github.io/sbmlsim-core/compiling/#a-batched-kernel) and [JavaScript](https://matthiaskoenig.github.io/sbmlsim-core/javascript/#the-batched-kernel).
